# KAVACH Web Application

KAVACH has a React supervisor website backed by a small local FastAPI adapter.
The existing CV, temporal intelligence, risk, SQLite, replay, and grounded
assistant modules remain the source of truth; the web layer does not
reimplement them.

## User flow

1. Open the website and upload a local video, or provide a direct HTTP(S)
   video-file URL.
2. Review source metadata and start analysis explicitly.
3. Watch the processed video with native controls, a position slider, incident
   markers, and 10-second backward/forward buttons. Selecting a **Needs
   attention** row jumps the player to that event's source timestamp.
4. Select an incident to read its evidence and risk breakdown. Signal frames in
   the processed video show a plain-English explanation banner, circle the
   involved YOLO/ByteTrack objects, and emphasize the relevant zone or
   relationship. Activity-only signals are deliberately treated as context,
   not as proof of unsafe behaviour.
5. Select **Play evidence clip**. KAVACH creates or reuses a clip covering up
   to three seconds on either side of the event and loads it into the player.
6. Ask a grounded question. Deterministic counts and filters are computed
   before optional Ollama wording, and returned event references can be
   replayed directly from the answer.

## Website structure

- **Overview** — source metadata, processing telemetry when available, review
  queue, evidence player, event timeline, and an operational readout.
- **Events** — behaviour, risk, and entity filters; evidence fields; risk
  breakdown; review status; replay.
- **Ask KAVACH** — grounded natural-language questions with timestamped
  references and replay actions.
- **Analytics** — behaviour frequency, risk distribution, event timeline, and
  a prioritized, selectable entity-to-incident evidence graph.

The graph shown in the website is intentionally labelled an **evidence graph**.
It is derived from incident records stored in SQLite. Module 6 scene-graph
snapshots are currently in-memory and are not claimed to be a persisted,
frame-by-frame graph.

## Processed-frame explanations

The output video is designed for inspection, not just decoration. When a
stored safety or anomaly signal is active, the top banner answers three
questions:

- **What happened?** — the configured signal type and the involved tracked
  object(s).
- **Why was it flagged?** — the geometry or temporal condition that fired.
- **What does the system not know?** — for example, image-space evidence is
  not proof of physical impact, damage, intent, or metres/second.

The circles and thick boxes identify the current tracked objects. For zone
signals, the relevant polygon is emphasized; for proximity/collision signals,
the relationship line is emphasized. On busy frames, duplicate headlines are
collapsed and secondary tracking labels are hidden so the safety explanation
stays readable.

## Start the website

Build the React bundle once:

```powershell
cd frontend
npm install
npm run build
cd ..
```

Start the local API from the repository root:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.api.main:app --host 0.0.0.0 --port 8000
```

Open `http://localhost:8000/`. The API serves the production React bundle
when `frontend/dist` exists, making this the simplest reproducible run mode.

For frontend development, run the API on port 8000 and use a second terminal:

```powershell
cd frontend
npm run dev -- --host 0.0.0.0 --port 5173
```

Then open `http://localhost:5173/`. Vite proxies `/api` requests to the local
API.

## Video replay behaviour

The processed video is served from `/api/videos/{video_id}/processed`. An
incident replay is generated only when requested and is served from
`/api/events/{event_id}/clip`. This keeps ordinary analysis from producing a
large collection of unnecessary clips. The browser's native seek bar and the
KAVACH transport controls operate on either source.

## Grounding boundary

The assistant receives structured event rows, risk evidence, statistics, and
configured rules. It does not receive raw video and does not decide whether a
visual event occurred. If the database does not contain enough evidence, the
answer should say so. Replay references are tied to event IDs and timestamps
returned by the database rather than generated by the model.

## Compatibility boundary

The Streamlit application remains available as a fallback for upstream
compatibility and comparison:

```powershell
streamlit run app/streamlit/app.py
```

The React website is the primary supervisor experience. The backend pipeline
is shared by both interfaces.
